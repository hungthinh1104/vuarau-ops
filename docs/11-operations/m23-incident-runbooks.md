# M23 pilot incident runbooks

Every incident record includes the full release SHA, UTC/local timestamps,
workspace, safe request/command/reference IDs, affected workflow and operator.
Never copy names, notes, amounts or credentials into general logs. Never edit
canonical business rows, ledgers, movements, command receipts or audit records.

| Symptom                                       | Safe first checks                                                                                                                                       | Evidence to collect                                                                              | Allowed remediation                                                                                | Must **not** do                                                                         | Severity                                                        |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| User cannot authenticate                      | confirm correct origin, network, Supabase status, issuer/JWKS and individual account; run `ops:check-env`/`ops:check-supabase` without printing secrets | request ID, timestamp, subject identifier, readiness result                                      | correct deployment config or account in the identity provider; retry after verified status         | share accounts, mint tokens, enable public sign-up, use E2E bridge                      | P1 for affected user; P0 if authentication boundary is bypassed |
| Wrong/missing permission                      | run `ops:pilot review`; compare role to signed ASM-017/018 review                                                                                       | actor/workspace IDs, current role/capabilities, refused procedure/code                           | owner uses authenticated membership command to assign the reviewed least-privilege role            | update membership SQL, grant owner “temporarily”, share an owner session                | P1 if task required; P0 for unauthorized access                 |
| Unknown command outcome after network failure | preserve the form and original command/idempotency identity; inspect sync/command outcome                                                               | command ID, idempotency key, request ID, client phase, receipt/audit/source resolution           | resend the identical command and inspect the authoritative detail                                  | mint a new identity, delete receipt, infer failure from a dropped response              | P1 until resolved; P0 if duplicate/lost effect appears          |
| Offline/sync problem                          | inspect durable outbox status, device connectivity and frozen queued snapshot                                                                           | outbox entry IDs/types/statuses, release SHA, last sync error—no business payload in shared logs | retry synchronization; leave queued Sale immutable; reconnect/reload                               | edit a queued command, clear storage before evidence, add manual duplicate Sale         | P1                                                              |
| Integrity attention                           | stop the affected workflow and open integrity/reconciliation reads                                                                                      | integrity result, source refs, command/audit correlation, projection/canonical counts            | use named rebuild only for disposable projections; use business compensation for mistakes          | edit/reorder/delete canonical entries, “fix” projection by changing source history      | P0 for corruption/cross-workspace/lost effect; otherwise P1     |
| Leaked/revoked document share                 | revoke the share through the command path and verify public read is denied                                                                              | document/share IDs, exposure window, access logs, ASM-030 policy contact                         | revoke, rotate by creating a new explicit share if policy permits, notify policy owner             | delete document snapshot/audit, expose another token in logs/chat                       | P0 for unauthorized real-customer exposure; otherwise P1        |
| Database unavailable                          | check `/health/live`, `/health/ready`, provider state and connection exhaustion                                                                         | probe result, provider incident ID, timestamps, safe structured logs                             | stop writes/traffic, recover service under deployment procedure, replay identical pending commands | point production at an ad-hoc database, restore over newer truth, hand-edit failed rows | P1; P0 if committed truth is lost/corrupt                       |
| Backup/restore failure                        | preserve source backup, target and logs; verify key/digest/provider IDs                                                                                 | release SHA, backup/PITR ID, recovery point, start/end, integrity and reconciliation results     | retry into a new empty recovery target after cause is understood                                   | overwrite live workspace, disable digest checks, claim an unrehearsed pass              | P1; P0 if no recoverable canonical copy exists                  |
| Accidental role assignment                    | suspend affected action, inspect membership/audit and effective permissions                                                                             | actor/workspace IDs, role before/after, command/audit IDs, access during exposure                | intended owner uses revoke/role-change command; review actions performed during exposure           | SQL role edit, erase audit, leave unintended owner active while investigating           | P0 if unauthorized effect occurred; otherwise P1                |

P0 stops the whole shadow pilot. P1 blocks the affected workflow until a fixed
release or operational remediation is verified. P2/P3 observations use the same
evidence format but may continue under the M23 contract.
